# S2.5 — MQTT 5.0 子集执行计划

- **依据**：[ADR-017](../adr/017-mqtt5-properties-and-compat.md)（已采纳，S2.5 实现）、设计文档 §4.8
- **状态**：✅ 完成（2026-11-08，见 §6 交付记录）
- **不动的东西**：MQTT 3.1.1 线上字节、`#broker_message.headers` 分工（properties 只进 `proto_meta`）、S2 已冻结的存储与订阅接口

## 1. 范围

| 项 | 做 | 说明 |
|---|---|---|
| CONNECT properties | ✅ | session expiry、receive maximum、maximum packet size、user properties、will delay（仅存储） |
| PUBLISH properties | ✅ | payload format、message expiry、content type、response topic、correlation data、user properties |
| SUBSCRIBE properties | ✅ | subscription identifier、user properties |
| reason codes | ✅ | v5 CONNACK/PUBACK/PUBREC/PUBREL/PUBCOMP/SUBACK/UNSUBACK/DISCONNECT 显式携带；`0x84` 修正协议版本不支持 |
| session expiry | ✅ | `clean_start` + expiry 决定会话保留；`.subs` 写入 `expires_at`，boot 清理过期会话 |
| `$share/{group}/{filter}` | ✅ | 解析为 `{shared, Group, Filter}`，复用 S2-D 的 Shared 投递 |
| topic alias / request-response | ❌ | 留 S5（ADR-017 §17.1） |

## 2. 实现步骤

1. **帧层**（`mqtt_frame.hrl` / `mqtt_frame.erl`）
   - record 尾部追加 `props`（以及 reason code 字段），既有字段顺序不动；3.1.1 路径不读写新字段。
   - 新增 `decode/2`（`Vsn = 4 | 5`）；`decode/1` 保持 3.1.1 语义。
   - 新增 properties 编解码：未知/重复 id 拒绝；变长整数用现有 varint。
   - v5 的 CONNECT/PUBLISH/SUBSCRIBE/UNSUBSCRIBE/握手帧/DISCONNECT 体解析；CONNACK/SUBACK/PUBACK 等出站编码。
2. **连接层**（`mqtt_conn_fsm.erl`）
   - `#st.proto_level`；所有出站 `send_frame` 带版本。
   - CONNECT v5：按 5 字节 CONNACK 形状应答，`0x84` 用于不支持的协议版本。
   - `receive_maximum` 参与 `max_inflight` 上限；`maximum_packet_size` 拒绝超限入站 PUBLISH（断开，不 ack）。
   - properties → `proto_meta`；message expiry → `expires_at`（与 ADR-015 TTL 合流）。
   - `$share` 语法 → Shared 订阅；v5 SUBSCRIBE options 只取 QoS 位。
   - PUBACK v5 reason code：有匹配订阅 0x00，无匹配 0x10。
   - session expiry：`.subs` 写 `expires_at`；boot 清理。
3. **测试**
   - `mqtt_frame_SUITE`：v5 properties 往返、未知 property 拒绝、3.1.1 字节不变、`0x84`。
   - `mqtt_conn_SUITE`：v5 CONNECT/CONNACK 形状、user properties 落 `proto_meta`、message expiry、`$share` 建组、receive maximum、PUBACK 0x10。
   - T15：paho-mqtt 5 真实客户端用例。
4. **文档**：`docs/protocol-compatibility.md` 拆 3.1.1 / 5.0 两行；`docs/architecture.md` 的 `proto_meta` 表；本计划 §6 交付记录。

## 3. 验收

- `rebar3 ct` 全绿、`dialyzer` 干净、`xref` 不新增未使用导出。
- 3.1.1 既有 388 例零回归（本阶段完成时点；S2-C/S2-D 等后续阶段已增至 `mqtt_conn_SUITE` 68 例，回归基线以当次 `rebar3 ct` 为准）。
- paho 5.0 客户端能连接、发布带 properties、订阅收消息、收到 `$share` 投递。

## 4. 风险

- properties 解析放宽会污染 3.1.1：用 `decode/2` 的版本参数隔离，3.1.1 永不读 properties 长度。
- `0x87 → 0x84` 会改变 v5 拒绝字节：旧 T15 断言需同步更新，3.1.1 路径不变。

## 5. 实现边界（已完成后的准确口径）

- 帧层 `decode/2` / `encode/2` 接受 `4 | 5`；`decode/1` / `encode/1` 保持 3.1.1 语义，3.1.1 路径不读 properties 长度。
- 未知 property id、重复单值 property id 一律拒绝；`user_properties` 累积保序。
- v5 出站：CONNACK/SUBACK/UNSUBACK/PUBACK/PUBREC/PUBREL/PUBCOMP 按 reason code + properties 长度编码。
- 级别 >= 5 的未知版本回 `20 03 00 84 00`；4/3 等回 3.1.1 的 `20 02 00 01`。
- `receive_maximum` 只收窄出站窗口（`min(max_inflight, ReceiveMaximum)`），不影响入站。
- `mqtt_max_packet_size` 默认 0（关闭）；非 0 时入站整帧超限断开且不 ack，出站 PUBLISH 超过客户端上限丢弃并计数。
- session expiry：`session_expiry_interval > 0` 才持久化；断开时写 `session_expires_at`；boot 时拆除过期会话。
- `$share/{group}/{filter}` 只做语法解析与 Shared 建组/退组；subscription identifier 记录在连接状态，不随投递帧回传（留 S5）。

# S12-D 立项 / 收敛调查：跨节点消息投递（2026-11-19）

> **性质**：本文是**立项前的收敛调查**，不是规格，也不是已批准设计。它把
> 「跨节点投递为什么不存在、要做到『一个逻辑 Broker』缺哪些件、有哪些互斥的路子、
> 各自撞上哪条冻结契约」钉成事实，**把裁决留给 S12-D 的 ADR**。先例同
> `s12-0-convergence-report.md` 与 `s11-protocol-candidates.md`：先证据，后裁决。
>
> **背景**：ADR-032 **D9** 已裁决 S12 不含跨节点投递，G2 达成口径收窄为
> 「多节点接入 + 分区归属可迁移 + 外部 LB 分发 + 会话粘性」，跨节点投递单列
> **S12-D** 并须新增 ADR。S12-A/B/C 交付后本仓仍是「多节点接入」而非
> 「一个逻辑 Broker」——A 节点订阅者收不到 B 节点 publish。本调查回答 S12-D 开工前
> 必须先答的问题：这件事到底缺什么、有哪些做法、代价与冻结边界是什么。

## 1. 现状：跨节点投递为什么不存在（代码级）

逐层钉死，全部是当前 S12 交付后的代码事实：

| 层 | 事实 | 位置 |
|---|---|---|
| **发布** | 发布进程在本地 `broker_router_hash:route(Topic, Ctx, Env)` 上拿到 `[{Partition, Refs}]`，`Refs` 是**本节点**路由索引里的订阅者；随后 `broker_queue:append(Partition, Msg, fsync)` 写**本节点**本地 WAL | `broker_proto_mqtt/src/mqtt_conn_fsm.erl:752,833` |
| **路由索引** | `broker_router` 的 store（`broker_router_hash`）是**每节点一份** ETS；`register/3` 把 SubRef 写进本地索引；`route/3` 是**本地读**的纯函数 | `broker_router/src/broker_router.erl:20-30`；ADR-010 §10.1 |
| **订阅 / 游标** | SubRef 由**本节点** `broker_subscription_worker` 铸造；消费者游标读的是**本节点** `broker_queue:watermarks(Partition)`（本地 WAL High 水位） | `broker_subscription/src/broker_subscription.erl:253`；`broker_subscription_worker` 本地 ETS |
| **投递** | 队列只 `notify` **本地**订阅 pid（`broker_queue:subscribe/2` 注册本地 pid）；投递一律本地 `Pid !` | `broker_queue/src/broker_queue.erl:288-290,325`；`broker_subscription.erl:219-233` |
| **集群层** | `broker_cluster` 的 ra 组只承载**归属元数据** `(owner, epoch, replicas, state, index)`；默认 `replicas_of` 回退到 `[node()]`（**仅 owner 自己**） | `broker_cluster_meta_machine.erl:96-100` |
| **复制** | `broker_cluster_rep:replicate/2` 把 owner 写拷给 replica set 并等多数派；但**follower 明确「不服务读、不通知本地订阅者」** | `broker_cluster_rep/src/broker_cluster_rep.erl:6-7,20-22` |

**直接推论**：发布方 B 把消息写进 B 的 WAL 分区 P；订阅方 A 的游标挂在 A 的**另一份**
WAL 分区 P 上；两份 WAL 在不同节点、从不交换字节。**默认 replica set = `[owner]`**，
所以连「拷给多数派」在默认配置下都是单节点空操作。结论：**没有任何路径把消息从
B 的队列送到 A 的订阅者**。`apps/*/src` 中 `pg`/`pg2`/`global`/`monitor_nodes`
**0 处**（`net_kernel` 只在 dist 测试里），投递一律本地 `Pid !`，副本刻意不通知
本地订阅者。

## 2. 「一个逻辑 Broker」缺的件

G2 若要收窄口径之外的完整承诺（多节点作为同一个 Broker），缺四件，且相互耦合：

1. **分区→节点的写入路由**——发布方必须把消息写到**持有该分区的节点**，而不是「本地
   hash」。当前 `route/3` 只给本地分区；owner 可能在别的节点。
2. **订阅者节点索引**——必须知道「分区 P 在本集群有哪些订阅者、分别在哪个节点」，才能
   扇出。这正是 ADR-010 冻结边界的核心冲突（见 §4）。
3. **跨节点扇出 + 全局游标**——消息必须到达每个持有订阅者的节点的本地 WAL；消费者的
   offset / cursor 语义要跨节点一致（谁读到哪、ack 归属、组消费的 row 分配）。
4. **归属迁移时的在途一致性**——owner 变了，发布方与新订阅者必须切到新 owner，且不
   丢不重（复用 S12 的 epoch fencing + 两阶段迁移，但要在数据面而非仅元数据面生效）。

## 3. 互斥的路子（候选池，未裁决）

| 路子 | 一句话 | 撞上的冻结契约 / 代价 |
|---|---|---|
| **A. 连接粘性即一切** | 不做数据面跨节点；靠 LB 把同一订阅者的连接与其发布目标都钉在同一 owner 节点。会话粘性（R-CL2/S12 已交付）已保证「连接不换节点」 | **不新增数据面**，但要求「发布与订阅同分区同节点」——多租户 / 发布订阅不在同一连接时无法成立；本质是「按分区 sharding，不是逻辑 Broker」 |
| **B. 全量复制 + 本地投递扇出** | 每条消息复制到**所有**节点（或所有持有该分区订阅者的节点），每节点本地投递给自己的订阅者；游标全局化 | 复制带宽 = 节点数 × 写入；cursor 对账是分布式难题；撞 ADR-010「Router 不持有消费者状态」——订阅者节点索引必须落到别处并**显式修订 ADR-010** |
| **C. owner 侧扇出 + 远程订阅者代理** | 消息只在 owner 的 WAL；owner 为每个远程订阅者维护一个轻量代理/转发器，把投递跨节点转回订阅者所在节点 | owner 成为扇出瓶颈与单点；订阅者节点要能反向连 owner（有状态连接）；迁移时要重挂代理；撞 ADR-019「消费者注册表本地 ETS、不跨节点」 |
| **D. 显式 sharding + 订阅重定向** | 订阅者按分区 owner 落位（建连时 LB 按分区视图路由，S12-A 已有 `/api/v1/node` + 分区视图）；跨节点同分区订阅通过重定向/代理（类比 S9-B 的「非 owner GetTask 返回重定向」） | 最贴近既有 S12 交付（复用节点视图 + drain + 再平衡）；但「同分区跨节点订阅」仍需代理层，且把路由约束暴露给客户端语义 |
| **E. 不做跨节点投递** | 明确把「多节点 Broker ≠ 一个逻辑 Broker」写进能力矩阵，G2 永久停在 S12 的收窄口径 | 零增量、零风险；与 ADR-032 D9 的方向一致；代价是 G2 的完整承诺**永久不交付**，需产品侧确认这就是终态 |

## 4. 冻结边界：S12-D 必然要碰的契约

跨节点投递不是「在既有缝里加个模块」，它**结构性冲突**以下已冻结决策，S12-D 的 ADR
必须显式处理，不能绕开：

- **ADR-010 §10.1（最硬的一条）**：`broker_router` 只持有 `Filter → [SubRef]` **倒排
  索引**、**不持有消费者状态**；`route/3` 是无状态纯函数、在调用方进程内读。§4.1 已点明
  「订阅者节点注册表本质是『消费者在哪个节点』的索引，会触及这条边界」。**路子 B/C/D
  都需要新增『订阅者→节点』这一维，等于修订 ADR-010**。
- **ADR-019 §19.2 / §19.5**：消费者注册表是**本地 ETS**、row 分配在 worker 内、`assigned`
  **不落盘**、投递是本地 `Pid !`。跨节点游标 / 组消费 row 分配要跨节点一致，**撞这条**。
- **ADR-021 D2 / D3**：集群层只承载归属元数据 + 两阶段迁移；数据面「只拷字节」。S12-D 若
  要让数据面跨节点，需在 ADR-021 的框架内扩展（而非另起一套共识），并复用 epoch fencing。
- **ADR-011 / ADR-007**：可用性承诺绑定 WAL 落盘 + 三档可靠性等级；跨节点投递的「不丢不重」
  必须绑定到这三档，不能含糊（同 roadmap §14「三条硬边界」）。
- **净新增运行时依赖 = 0 / 不新增 app / 不新增端口 / 不引入第二套共识**（ADR-003 / roadmap
  硬边界）：路子 B 的全量复制要小心别变成「第二套真相」。

## 5. 建议的下一步（不预设裁决）

1. **先做产品裁决**：G2 的终态到底是「一个逻辑 Broker」（要跨节点投递）还是「分区
   sharding 的多节点接入」（不要）？这决定 S12-D 是否开工。若选后者，路子 **E** 即终态，
   只需在能力矩阵把「跨节点投递不做」写死，S12-D 关闭为「won't do」。
2. **若要做跨节点投递**：S12-D 的第一个动作是**新增 ADR**，显式裁决 §3 里的 A~D 之一
   （或组合），并显式修订 ADR-010 / ADR-019 的相关边界；ADR 冻结后再谈实现分期。参考
   路子 **D**（复用 S12 的节点视图 + drain + 再平衡 + epoch fencing）与既有 S12 交付最同构，
   增量面最小，但仍需解决「同分区跨节点订阅」的代理层。
3. **不引入任何代码改动**：本文是调查，未改任何源码 / 测试 / 配置。所有跨节点投递的
   现有结论仍只由 §1 的代码事实支撑。

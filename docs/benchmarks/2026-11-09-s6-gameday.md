## 结果总览

| # | 场景 | 破坏的不变量 | 实测恢复/表现 | 结论 |
|---|---|---|---|---|
| 1 | `crash` | 进程 `kill -9`，有 in-flight durable QoS1 | 重启到 CONNACK **3.956 s**；会话仍在；消息重投且 payload 一致 | ✅ pass |
| 2 | `slow_consumer` | 订阅者永不 ack | 20000 条 20 s 内发布完，broker 存活；RSS 134.0→176.8 MiB（**+42.8**）；慢消费者收到 0 条 | ✅ pass |
| 3 | `disk_readonly` | 数据目录中途变只读（真实只读 bind mount / EROFS） | 拒启；不 ACK 未持久化的写；恢复只读后重启 **3.559 s**；durable 消息存活、会话在 | ✅ pass |
| 4 | `partition` | 3 节点 Metadata Raft 组杀 Leader | `broker_cluster_dist_SUITE` 4/4（25.0 s），含 Leader 故障切换后继续提交、失去多数派拒绝 | ✅ pass |

## 1. 崩溃（crash）

- 注入：客户端已收到 PUBACK 的 durable 消息之外，另有一条已入 WAL、尚未 ACK 的
  QoS1 消息；`docker kill -s KILL`。
- 恢复：容器重启 → `broker_storage_wal:recover/2` → 分区 worker 重建 → listener 起来。
- 断言：
  - 首个 CONNACK 用时 **3.956 s**（从 `docker start` 到 socket 可读）。
  - 持久会话仍在（`session_present = true`）。
  - 重启后订阅者收到那条 in-flight 消息，payload 字节一致。
- 解读：`kill -9` 只丢 os_buffer 窗口；durable（fsync）消息在 ACK 前已落盘，必达。

## 2. 慢消费者（slow_consumer）

- 注入：一个订阅连接建立后从不发送 PUBACK；同时 8 个生产者持续发布 20000 条。
- 断言：
  - 发布在 **15.2 s** 内完成（broker 不被一个慢消费者拖死）。
  - broker 进程存活（`broker_alive = true`）。
  - 慢消费者收到 **0** 条（窗口满后不再投递，符合背压语义）。
  - RSS 从 134.0 MiB 涨到 176.8 MiB（**+42.8**，采样 36 次），有界、无 OOM。
- 解读：S2-G 的 pull round permit + `max_inflight` 生效；慢消费者被隔离，积压钉在
  它自己的 cursor 上，不阻塞其他订阅者。

## 3. 磁盘只读（disk_readonly）

- 注入：用**真实只读 bind mount**（`mount --bind` + `remount,ro`，EROFS）把数据目录
  变只读，而不是 `chmod`——已打开的 WAL fd 会忽略权限位，`chmod` 不能真正模拟磁盘故障。
- 断言：
  - 只读状态下 broker **拒启**（`refused_to_boot = true`）。
  - 不 ACK 它没有持久化的写（`ack_withheld = true`）。
  - 恢复可写后重启用时 **3.559 s**。
  - durable 消息存活、持久会话仍在。
- 解读：写失败即拒绝 ACK 是 ACK 契约的硬要求；恢复路径从 WAL 重放，未因半写损坏。

## 4. 网络分区 / Leader 故障（partition）

- 注入：3 个 `peer` 节点组成 Metadata Raft Group；杀掉 Leader，观察多数派是否继续提交，
  再移除到只剩 1/3 验证「无多数派拒绝写」。
- 断言：`broker_cluster_dist_SUITE` **4/4 通过**（25.0 s），覆盖：
  - 三节点组形成 + 复制；
  - Leader 故障切换后继续提交；
  - 失去多数派 `{error, no_quorum}`；
  - 迁移后旧 Owner 被 Fencing 拒绝。
- 解读：Raft 层用 `ra` 3.2.0，数据面 `replicated_commit` 只在多数派 ACK 后返回
  （见容量报告 §6 的 2/3、3/3、1/3 数字）。

---

## 结论

四类故障均在可接受时间内恢复，且**没有一条 durable 消息被静默丢弃**，没有一条未持久化的
消息被错误 ACK，慢消费者不拖垮 broker。这些是 Gate S6 第 3 项要求的实测恢复时间证据。

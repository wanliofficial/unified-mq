# S12-D 跨节点消息投递的延迟实测（2026-11-19）

> 本报告回答 Gate S12 的「容量与迁移报告」一项中跨节点投递的部分：把 ADR-034 三条
> 跨节点**读/写热路径**走通分布式的**单次调用延迟**实际测出来。方法、原始数字与口径
> 限制都在下面，数字是本机、同主机、2 peer 下各 3 轮运行中位数的结果，**不是**跨机、
> 跨地域的结论。迁移耗时另见 [`2026-11-19-s12c-rebalance.md`](2026-11-19-s12c-rebalance.md)。

## 1. 测了什么

ADR-034 的裁决形状 D′ 是「一个分区只有 owner 的一份权威日志，publish 路由到 owner
写、订阅者从 owner pull 读」。落到调用路径上，跨节点代价只体现在三类操作，各加一条
**本地基线**用于隔离路由开销：

| 代号 | 操作 | 走的路径 |
|---|---|---|
| **D0** | `broker_queue:append/3`（在 owner 上） | 本地写，无转发——**下界** |
| **D2** | `broker_queue:append/3`（在非 owner 上） | 路由钩子 → `rpc:call` 转发到 owner → owner 写 → 回传 |
| **D3** | `broker_queue:read_from/3`（在非 owner 上） | 路由钩子 → 转发到 owner → owner 读日志 → 回传页 |
| **D4** | `broker_subscription:dispatch/2`（QoS0，owner 上） | 本地投递 + `rpc:cast` 广播给其他成员（**发布方侧成本**） |

被测对象全部走**真实路径**：2 个 `peer:start_link` 起的独立 BEAM 节点，真实 `ra`
集群（本机磁盘 WAL）、真实 `broker_cluster_cache` 本地镜像、真实路由钩子（`install_hooks/0`
装好，`cross_node_delivery = true`）。没有 mock。D2 的非 owner 与 owner 由测试经
`broker_cluster_cache` 显式指定（owner 恒为 N2），因此转发一定发生。

## 2. 原始数字

`n = 200` 次/操作，同一台主机，2 个 peer。每操作先跑 20 次 warmup（不计入），再测 3
轮取中位数。延迟为墙钟时间（`erlang:monotonic_time`），单位 µs。

| 操作 | p50 | p95 | p99 | max |
|---|---|---|---|---|
| **D0** 本地 append（owner，下界） | **1996** | 2125 | 2677 | 3315 |
| **D2** 跨节点 append（非 owner → owner） | **2963** | 3650 | 3500 | 6380 |
| **D3** 跨节点 read（非 owner → owner） | **1386** | 1541 | 1928 | 2433 |
| **D4** QoS0 dispatch（发布方侧，含 cast 广播） | **316** | 443 | 837 | 7345 |

> 复跑口径：3 轮 D0 p50 = 1995.7 / 1996.3 / 1996.6 µs，D2 = 2927 / 2963 / 2988 µs，
> D3 = 1378 / 1379 / 1402 µs，D4 = 316.3 / 316.7 / 324 µs。轮间稳定。

## 3. 怎么读这些数字

**本地写本身就是主导项，不是路由。** D0（owner 本地 append）p50 已经 **2.0 ms**——这是
`fsync` 同步复制到多数派的代价（ra 提交），与跨节点无关。换句话说，即便没有跨节点
投递，一条持久化消息的落盘成本就在 2 ms 量级。

**跨节点转发在 D0 之上增加约 1 ms（D2）。** D2 跨节点 append p50 **2.96 ms** =
D0 的 2.0 ms + 约 1 ms 的**转发 RPC 往返**。这 1 ms 是同主机分布式的 `rpc:call`
序列化 + 反序列化 + socket RTT，纯路径开销。含义：

- **跨节点写不是免费的，但代价可预测、且是常数级**（与队列深度、消息大小无关，转发的是
  调用不是数据搬运——数据始终只在 owner 的 WAL 里，见 ADR-034 D2「无本地双写」）。
- 相对 D0 的 2 ms 落盘成本，转发的 1 ms 是**可接受的额外一跳**：写放大没有变（只写一份），
  只是多了一跳网络。这正是 D′ 相对「全量复制」路线的取舍——**用一次转发换「全仓只有一份
  日志」**。

**读比写便宜（D3 < D0）。** D3 跨节点 read p50 **1.39 ms**，比 append 更低，因为读路径
只是 owner 读一页日志回传、无 fsync、无 raft 提交。这是 ADR-034 明示的 **owner 读热点**
代价（D3 签认问题 3）：所有读都汇聚到 owner，但单次读是亚毫秒级、无共识开销。

**QoS0 发布方侧几乎免费（D4）。** D4 p50 **316 µs**，远低于持久化写——因为 QoS0 不进日志、
不 fsync、不 raft 提交，dispatch 只做本地索引查找 + `rpc:cast`（fire-and-forget）。这正是
ADR-007 L1「QoS0 不承诺持久性，故不阻塞发布方」的延迟体现。**max 7.3 ms** 是 cast 偶发
调度抖动，不进入 p99 主体，符合「尽力而为、不保证尾延迟」的定性。

两个具体含义：

- **转发开销 ≪ 落盘开销。** 跨节点写比本地写贵约 50%（2.0 → 3.0 ms），但两者都在「毫秒级
  单次调用」区间，且转发是确定的 +1 ms、不是数量级的恶化。**owner 读热点不构成延迟风险**
  ——读反而比写便宜。
- **QoS0 与持久化写的延迟差了一个数量级**（0.3 ms vs 3.0 ms），印证了「QoS0 走 L1 快路径、
  QoS1/2 走 raft 慢路径」的分层是真实生效的，不是纸面承诺。

## 4. 口径限制（别外推）

- **同主机、单机、2 节点。** 这是**下界**。跨机、跨 AZ 时分布式的 socket RTT 会成为转发
  的主导项：D2/D3 的「+1 ms 转发」在跨 AZ（RTT ~1 ms）时会**翻倍甚至更多**（一来一回各
  一个 RTT + 序列化），跨地域（RTT ~30~60 ms）会到**几十 ms**。**本仓没有跨机集群证据**，
  以上是基于同主机 RTT 的推算。D0 的 2 ms 落盘成本跨机变化不大（fsync 是本地的），但跨机
  的 raft 提交会多一个跨网 RTT。
- **串行测量，无并发。** 所有样本串行执行。并发 appender 会被 owner 的 raft 提交天然排队，
  尾延迟（p99/max）会随并发上升，未测。
- **D4 只测发布方侧。** dispatch 的延迟是「发布方发出 cast」的阻塞成本；对端成员收到并
  投递是异步的、不在发布方的关键路径上，因此不可从本报告读出「端到端投递延迟」——那需要
  跨节点的时钟同步与相关 id 关联，本仓未做。
- **冷路径已预热。** 20 次 warmup 不计入，因此没有模块加载、leader 首次发现、缓存冷填充
  的一次性成本。生产环境首次跨节点调用可能慢一个数量级，属正常。
- **消息固定小尺寸。** msg 是定长小消息。大消息的转发会多一次序列化/拷贝成本，未测。

## 5. 结论

ADR-034 的跨节点投递在延迟上是**「本地成本 + 一次可预测转发」**，不是数量级恶化：

- 持久化写：本地 2.0 ms，跨节点 3.0 ms（**+1 ms 转发**，同主机下界）。
- 跨节点读：1.4 ms（比写便宜，印证 owner 读热点可接受）。
- QoS0 发布方侧：0.3 ms（L1 快路径，比持久化写快一个数量级）。

真正的边界是**同主机下界**与**无并发/无跨机**：跨机的转发 RPC RTT 会把 D2/D3 的 +1 ms
放大到跨网 RTT 量级，本仓当前无跨机集群证据。与 S12-C 一致——**元数据/路由操作是毫秒级、
对业务不构成数量级风险**，代价集中在「一次转发跳」而非「写放大」。
